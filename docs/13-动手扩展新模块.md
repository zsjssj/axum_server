# 13 动手扩展新模块

**本章目标**：把前面 12 章的知识串起来，从零加一个完整业务模块。做完这一章，你就具备了"在这个项目里独立干活"的能力。

**任务**：实现「笔记（notes）」模块——每个用户只能看到和删除自己的笔记。相比用户模块，它多了一个新东西：**数据归属**（ownership）。

- `POST /api/v1/notes` 创建笔记
- `GET /api/v1/notes` 分页列出我的笔记
- `DELETE /api/v1/notes/{public_id}` 删除我的一条笔记

## 13.2 第 1 步：迁移

新建 `migrations/003_create_notes_table.sql`：

```sql
-- 笔记表：每个用户拥有自己的笔记。
-- 归属关系用 user_id 外键表达，删除用户时笔记一起删除（ON DELETE CASCADE）。

CREATE TABLE IF NOT EXISTS notes (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    public_id UUID NOT NULL UNIQUE,
    user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(200) NOT NULL,
    content TEXT NOT NULL DEFAULT '',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- "我的笔记列表"按创建时间倒序，索引顺序与查询的 WHERE + ORDER BY 对齐。
CREATE INDEX IF NOT EXISTS idx_notes_user_created
    ON notes(user_id, created_at DESC);
```

三个决定：

| 决定 | 原因 |
| --- | --- |
| 同样用 `id` + `public_id` 双 ID | 与 `users` 保持一致：内部关联用 `id`，对外用 `public_id` |
| `ON DELETE CASCADE` | 用户删除后笔记无意义，交给数据库保证 |
| 索引 `(user_id, created_at DESC)` | 同时覆盖 `WHERE user_id = $1` 和 `ORDER BY created_at DESC`，一条索引解决两个条件 |

启动一次服务验证：

```bash
cargo run
# 另开终端
psql -c "SELECT version, description FROM _sqlx_migrations;"
```

看到 `003` 出现即成功。**之后不要再改这个文件**（改了会让下次启动校验和失败）。

## 13.3 第 2 步：模型

新建 `src/modules/note/model.rs`：

```rust
use chrono::{DateTime, Utc};
use serde::{Deserialize, Serialize};
use sqlx::FromRow;
use utoipa::ToSchema;
use uuid::Uuid;
use validator::Validate;

/// 笔记实体。
///
/// 不包含 `user_id`：调用方只关心内容，归属关系由服务端根据令牌决定。
/// 时间用 `DateTime<Utc>`（对应 `TIMESTAMPTZ`），serde 默认输出 RFC3339，
/// 不需要自定义格式。
#[derive(Debug, Serialize, Deserialize, FromRow, ToSchema)]
pub struct Note {
    pub public_id: Uuid,
    pub title: String,
    pub content: String,
    pub created_at: DateTime<Utc>,
    pub updated_at: DateTime<Utc>,
}

/// 创建笔记请求。
#[derive(Debug, Deserialize, ToSchema, Validate)]
#[serde(deny_unknown_fields)]
pub struct CreateNoteRequest {
    #[validate(length(min = 1, max = 200, message = "标题长度必须在 1 到 200 个字符之间"))]
    #[schema(min_length = 1, max_length = 200)]
    pub title: String,

    /// 内容允许为空（草稿），但必须有长度上限，防止超大 payload 占用存储。
    #[validate(length(max = 20_000, message = "内容长度不能超过 20000 个字符"))]
    #[schema(max_length = 20_000)]
    pub content: String,
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn rejects_empty_title() {
        let request = CreateNoteRequest {
            title: String::new(),
            content: "内容".to_owned(),
        };

        let errors = request.validate().expect_err("空标题应校验失败");
        assert!(errors.field_errors().contains_key("title"));
    }
}
```

三个决定：

**① 实体里没有 `user_id`。** 归属是服务端的概念，不该出现在响应里（避免泄露"这条笔记属于谁"）。查询时用 `user_id` 过滤，但返回时不带它。

**② 用 `DateTime<Utc>` 而不是 `NaiveDateTime`。** 配 `TIMESTAMPTZ` 语义正确，且 serde 默认就输出 RFC3339，**不需要自定义序列化**——这正好呼应[第 10 章](./10-Redis与降级设计.md)那个"自定义序列化必须配套自定义反序列化"的坑。不自定义就不会踩。

**③ `content` 有长度上限。** 即使允许为空，也必须有上限。没有上限的 `TEXT` 字段是一个"存储放大"入口：一次请求塞进 50MB，日志和备份都会被拖垮。

## 13.4 第 3 步：Repository

新建 `src/modules/note/repository.rs`：

```rust
use chrono::{DateTime, Utc};
use sqlx::PgPool;
use uuid::Uuid;

use crate::modules::note::model::Note;

/// 笔记数据访问层。
pub struct NoteRepository;

impl NoteRepository {
    /// 创建笔记。归属关系由 `user_id` 参数决定，不由请求体决定。
    pub async fn create(
        db: &PgPool,
        public_id: Uuid,
        user_id: i64,
        title: &str,
        content: &str,
        now: DateTime<Utc>,
    ) -> Result<Note, sqlx::Error> {
        let note = sqlx::query_as::<_, Note>(
            r#"
            INSERT INTO notes (public_id, user_id, title, content, created_at, updated_at)
            VALUES ($1, $2, $3, $4, $5, $5)
            RETURNING public_id, title, content, created_at, updated_at
            "#,
        )
        .bind(public_id)
        .bind(user_id)
        .bind(title)
        .bind(content)
        .bind(now)
        .fetch_one(db)
        .await?;

        Ok(note)
    }

    /// 按归属查询：`AND user_id = $2` 是**权限检查**，不是过滤条件。
    pub async fn find_by_public_id(
        db: &PgPool,
        public_id: Uuid,
        user_id: i64,
    ) -> Result<Option<Note>, sqlx::Error> {
        let note = sqlx::query_as::<_, Note>(
            r#"
            SELECT public_id, title, content, created_at, updated_at
            FROM notes
            WHERE public_id = $1 AND user_id = $2
            "#,
        )
        .bind(public_id)
        .bind(user_id)
        .fetch_optional(db)
        .await?;

        Ok(note)
    }

    /// 分页列出某个用户的笔记，按创建时间倒序。
    pub async fn find_all_by_user(
        db: &PgPool,
        user_id: i64,
        limit: i64,
        offset: i64,
    ) -> Result<Vec<Note>, sqlx::Error> {
        let notes = sqlx::query_as::<_, Note>(
            r#"
            SELECT public_id, title, content, created_at, updated_at
            FROM notes
            WHERE user_id = $1
            ORDER BY created_at DESC
            LIMIT $2 OFFSET $3
            "#,
        )
        .bind(user_id)
        .bind(limit)
        .bind(offset)
        .fetch_all(db)
        .await?;

        Ok(notes)
    }

    /// 统计某个用户的笔记总数。
    pub async fn count_by_user(db: &PgPool, user_id: i64) -> Result<i64, sqlx::Error> {
        let (count,): (i64,) =
            sqlx::query_as("SELECT COUNT(*) FROM notes WHERE user_id = $1")
                .bind(user_id)
                .fetch_one(db)
                .await?;

        Ok(count)
    }

    /// 删除自己的笔记，返回是否真的删掉了一行。
    pub async fn delete(db: &PgPool, public_id: Uuid, user_id: i64) -> Result<bool, sqlx::Error> {
        let result = sqlx::query("DELETE FROM notes WHERE public_id = $1 AND user_id = $2")
            .bind(public_id)
            .bind(user_id)
            .execute(db)
            .await?;

        Ok(result.rows_affected() > 0)
    }
}
```

**这一节最重要的一行是 `AND user_id = $2`。**

### 权限检查必须写在 SQL 里，不能只写在 Service 里

反面写法（错误）：

```rust
// ❌ 先查出来，再在 Rust 里比较归属
let note = NoteRepository::find_by_public_id(db, public_id).await?;   // 没有 user_id 条件
if note.user_id != current_user.user_id {
    return Err(AppError::NotFound("笔记不存在"));
}
```

看起来也能工作，但有三个问题：

1. **多一次判断，多一个漏写的可能**。任何新增的查询方法都忘了加这个检查，就是一个越权漏洞。
2. **时序上多一个信息泄露窗口**：数据已经到了应用内存里，日志、panic、调试输出都可能把它带出去。
3. **性能**：数据库可以用 `(user_id, public_id)` 一次命中，你却在应用层做过滤。

所以本项目把这个原则扩展成一条通用规则：

> **数据归属是数据访问层的一部分，不是业务层的补丁。** 把 `user_id` 写进 `WHERE`，让"看不到别人的数据"成为数据库返回的结果，而不是应用代码的判断。

顺带一个细节：`WHERE public_id = $1 AND user_id = $2` 查不到时返回 `Ok(None)`，Service 会转成 **404 而不是 403**。这是刻意的——403 会告诉攻击者"这条记录存在，只是不属于你"，等于送了一个探测接口。

## 13.5 第 4 步：Service

新建 `src/modules/note/service.rs`：

```rust
use chrono::Utc;
use sqlx::PgPool;
use uuid::Uuid;

use crate::common::error::AppError;
use crate::modules::note::model::{CreateNoteRequest, Note};
use crate::modules::note::repository::NoteRepository;

/// 笔记业务逻辑层。
pub struct NoteService;

impl NoteService {
    /// 创建笔记。
    ///
    /// 归属取自认证上下文（`user_id` 来自令牌的 `sub`），**绝不从请求体读取**：
    /// 否则任何客户端都能替别人创建笔记。
    pub async fn create_note(
        db: &PgPool,
        user_id: i64,
        req: CreateNoteRequest,
    ) -> Result<Note, AppError> {
        let public_id = Uuid::now_v7();
        let now = Utc::now();

        let note = NoteRepository::create(db, public_id, user_id, &req.title, &req.content, now)
            .await?;

        Ok(note)
    }

    /// 列出当前用户的笔记（分页）。
    pub async fn list_my_notes(
        db: &PgPool,
        user_id: i64,
        page: i64,
        page_size: i64,
    ) -> Result<(Vec<Note>, i64), AppError> {
        let offset = (page - 1) * page_size;

        let notes = NoteRepository::find_all_by_user(db, user_id, page_size, offset).await?;
        let total = NoteRepository::count_by_user(db, user_id).await?;

        Ok((notes, total))
    }

    /// 删除自己的笔记。
    ///
    /// 删不到时返回 404 而不是 403：403 会泄露"这条记录存在"。
    pub async fn delete_note(db: &PgPool, user_id: i64, public_id: Uuid) -> Result<(), AppError> {
        let deleted = NoteRepository::delete(db, public_id, user_id).await?;

        if !deleted {
            return Err(AppError::NotFound("笔记不存在"));
        }

        Ok(())
    }
}
```

三个决定：

**① `user_id` 是参数，不是请求体字段。** Handler 从 `CurrentUser` 取，Service 只接收。这样"能不能替别人创建"这个问题从类型上就不可能发生——请求体里根本没有这个字段（`CreateNoteRequest` 也没有，`deny_unknown_fields` 还会拒绝多余字段）。

**② 没有缓存。** 笔记列表会因任意一次写入失效，缓存命中率低、失效成本高——和用户列表不做缓存是同一个理由（`src/modules/user/service.rs:49`）。单条笔记也不缓存：它的访问频率远低于用户详情，而正确性代价相同。

**③ 删不到返回 404。** 统一"不存在"和"不属于我"，见上一节。

## 13.6 第 5 步：Handler

新建 `src/modules/note/handler.rs`：

```rust
use axum::{
    Router,
    extract::State,
    http::StatusCode,
    response::{IntoResponse, Json},
    routing::{delete, get},
};
use uuid::Uuid;

use crate::app::state::AppState;
use crate::common::{
    auth_extractor::CurrentUser,
    error::{AppError, ErrorData},
    extractor::{ApiPath, ValidatedJson, ValidatedQuery},
    pagination::{PaginatedResponse, Pagination},
    response::{ApiResponse, EmptyData},
};
use crate::modules::note::{
    model::{CreateNoteRequest, Note},
    service::NoteService,
};

/// 笔记路由。
///
/// 挂在 `/api/v1` 之下即自动受认证中间件保护，无需在此声明。
/// Handler 签名中的 `CurrentUser` 只用于表达"该接口需要身份"并读取用户 ID。
pub fn routes() -> Router<AppState> {
    Router::new()
        .route("/notes", get(list_notes).post(create_note))
        .route("/notes/:public_id", delete(delete_note))
}

/// 创建笔记
#[utoipa::path(
    post,
    path = "/api/v1/notes",
    tag = "笔记",
    request_body = CreateNoteRequest,
    responses(
        (status = 201, description = "笔记创建成功", body = ApiResponse<Note>),
        (status = 400, description = "JSON 请求体格式错误", body = ApiResponse<ErrorData>),
        (status = 401, description = "未登录或登录已过期", body = ApiResponse<ErrorData>),
        (status = 415, description = "请求体媒体类型错误", body = ApiResponse<ErrorData>),
        (status = 422, description = "请求参数校验失败", body = ApiResponse<ErrorData>),
        (status = 500, description = "服务器内部错误", body = ApiResponse<ErrorData>)
    )
)]
pub(crate) async fn create_note(
    State(state): State<AppState>,
    current_user: CurrentUser,
    ValidatedJson(req): ValidatedJson<CreateNoteRequest>,
) -> Result<impl IntoResponse, AppError> {
    let note = NoteService::create_note(&state.db, current_user.user_id, req).await?;

    Ok((StatusCode::CREATED, Json(ApiResponse::success("笔记创建成功", note))))
}

/// 我的笔记列表
#[utoipa::path(
    get,
    path = "/api/v1/notes",
    tag = "笔记",
    params(Pagination),
    responses(
        (status = 200, description = "分页笔记列表", body = ApiResponse<PaginatedResponse<Note>>),
        (status = 400, description = "查询参数格式错误", body = ApiResponse<ErrorData>),
        (status = 401, description = "未登录或登录已过期", body = ApiResponse<ErrorData>),
        (status = 422, description = "分页参数校验失败", body = ApiResponse<ErrorData>),
        (status = 500, description = "服务器内部错误", body = ApiResponse<ErrorData>)
    )
)]
pub(crate) async fn list_notes(
    State(state): State<AppState>,
    current_user: CurrentUser,
    ValidatedQuery(pagination): ValidatedQuery<Pagination>,
) -> Result<impl IntoResponse, AppError> {
    let (notes, total) = NoteService::list_my_notes(
        &state.db,
        current_user.user_id,
        pagination.page(),
        pagination.page_size(),
    )
    .await?;

    Ok(Json(ApiResponse::success(
        "查询成功",
        PaginatedResponse::new(notes, total, &pagination),
    )))
}

/// 删除笔记
#[utoipa::path(
    delete,
    path = "/api/v1/notes/{public_id}",
    tag = "笔记",
    params(("public_id" = Uuid, Path, description = "笔记公开 ID（UUIDv7）")),
    responses(
        (status = 200, description = "笔记删除成功", body = ApiResponse<EmptyData>),
        (status = 400, description = "路径参数格式错误", body = ApiResponse<ErrorData>),
        (status = 401, description = "未登录或登录已过期", body = ApiResponse<ErrorData>),
        (status = 404, description = "笔记不存在", body = ApiResponse<ErrorData>),
        (status = 500, description = "服务器内部错误", body = ApiResponse<ErrorData>)
    )
)]
pub(crate) async fn delete_note(
    State(state): State<AppState>,
    current_user: CurrentUser,
    ApiPath(public_id): ApiPath<Uuid>,
) -> Result<impl IntoResponse, AppError> {
    NoteService::delete_note(&state.db, current_user.user_id, public_id).await?;

    Ok(Json(ApiResponse::<()>::success_without_data("笔记删除成功")))
}
```

三个细节：

**① 参数顺序**：`State` → `CurrentUser` → `ApiPath`（都是 `FromRequestParts`）→ `ValidatedJson`（`FromRequest`，必须最后）。见[第 05 章](./05-请求生命周期.md)。

**② 每个受保护接口都声明了 401**。这不是可选的——注解是调用方判断"要不要登录"的唯一依据（[第 12 章](./12-API文档与测试.md)）。

**③ `delete` 用 `routing::delete` 导入**，而不是 `axum::routing::delete` 全路径。注意和 `UserRepository::delete` 同名不冲突（一个在 `routing`，一个是类型方法）。

## 13.8 第 10 步：测试与验证

### 先手工验证

```bash
# 1. 登录（令牌存 cookie 文件）
curl -c cookies.txt -X POST http://127.0.0.1:3000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"你的口令"}'

# 2. 创建笔记
curl -b cookies.txt -X POST http://127.0.0.1:3000/api/v1/notes \
  -H "Content-Type: application/json" \
  -d '{"title":"第一篇","content":"hello notes"}'

# 3. 列表
curl -b cookies.txt "http://127.0.0.1:3000/api/v1/notes?page=1&page_size=10"

# 4. 未登录必须 401
curl -X GET http://127.0.0.1:3000/api/v1/notes

# 5. 校验：空标题 → 422；未知字段 → 422
curl -b cookies.txt -X POST http://127.0.0.1:3000/api/v1/notes \
  -H "Content-Type: application/json" -d '{"title":"","content":"x"}'
curl -b cookies.txt -X POST http://127.0.0.1:3000/api/v1/notes \
  -H "Content-Type: application/json" -d '{"title":"t","content":"x","user_id":1}'
```

第 5 条的第二例必须失败——这是"归属不能由客户端指定"的验证。因为 `CreateNoteRequest` 有 `deny_unknown_fields`，`user_id` 会被拒绝。

### 再补自动化测试

## 13.9 常见错误排查表

| 现象 | 原因 |
| --- | --- |
| 编译报 `unresolved module note` | 忘了改 `src/modules/mod.rs` |
| 接口 404 | 忘了在 `api_routes` 里 `merge(note::routes())` |
| Swagger 里没有新接口 | 忘了在 `openapi.rs` 的 `paths(...)` 里注册 |
| Swagger 里有接口但没有 Schema | 忘了在 `components(schemas(...))` 里注册模型 |
| 启动报 `relation "notes" does not exist` | 迁移没建或没重新编译（`sqlx::migrate!` 是编译期宏） |
| 启动报迁移校验和不匹配 | 改了已执行的迁移文件 → 新增一个迁移来修正 |
| 接口返回 422 且提示"未知字段" | 请求体多传了字段，`deny_unknown_fields` 拒绝了它 |
| Handler 编译报 trait 约束错误 | 参数顺序错了（body 提取器不在最后） |
| 能创建笔记但列表永远是空 | 检查 `user_id` 是否真的从 `CurrentUser` 传入，且插入/查询用的是同一个 |
| 任何用户都能删别人的笔记 | `WHERE` 里漏了 `AND user_id = $2` |

## 13.10 进阶任务

按难度递增，每个都对应一个真实工程问题：

1. **更新笔记**：加 `PUT /api/v1/notes/{public_id}`。注意 `COALESCE` 的"无法清空字段"限制（[第 04 章](./04-数据库与SQLx.md)），想清楚"清空内容"该怎么表达。
2. **软删除**：加 `deleted_at TIMESTAMPTZ`，所有查询加 `WHERE deleted_at IS NULL`。思考：索引该怎么建？部分索引（`WHERE deleted_at IS NULL`）是否更合适？
3. **并发更新**：两个人同时改同一条笔记，后写的覆盖前者。加一个 `version BIGINT` 字段做乐观锁，`UPDATE ... WHERE version = $n`，`rows_affected() == 0` 时返回 409。
4. **搜索**：加 `GET /api/v1/notes?q=关键词`。先用 `ILIKE`，再研究 PostgreSQL 的 `tsvector` + GIN 索引，对比两者在 10 万行数据上的表现。
5. **越权测试**：用两个账号 A、B，验证 B 删除 A 的笔记返回 404（不是 403），并且 A 的笔记仍然存在。
6. **缓存**：给单条笔记加 Cache-Aside 缓存。**先想清楚失效策略**——笔记是"每人可见"的，键里必须带 `user_id` 或干脆不缓存。
7. **给用户加笔记数**：`GET /api/v1/auth/me` 返回 `note_count`。思考：每次都 `COUNT` 还是加冗余字段？各自的一致性代价是什么？
